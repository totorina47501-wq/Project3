# BLOC 3 — Premier moteur IA MentionCheck

Chemin : docs/03-ai.md
Statut : code proposé dans la branche, vérification CI et Supabase réelle nécessaires.

## Fonctions livrées

- lib/ai/mentioncheck-engine.ts : orchestration, événements SSE, écriture Supabase, horodatage et empreinte.
- lib/ai/text-analyzer.ts : règles déterministes et GPT-4o texte.
- lib/ai/vision-analyzer.ts : observation des marques, codes promotionnels et présence de personnes (sans identification).
- lib/ai/rewriter.ts : réécriture en français et explication des modifications.
- lib/ai/prompts.ts : prompts versionnés et protégés des instructions du contenu analysé.
- lib/ai/schemas.ts : Zod et types partagés.
- lib/openai.ts : OpenAI GPT-4o, store:false, timeout, retries, coût IA estimatif.
- app/api/check/route.ts : validation, identité, quotas et SSE.
- app/api/media/upload-url/route.ts : transfert dans Storage privé.
- app/api/rewrite/accept/route.ts : acceptation explicite avec consentement de fine-tuning mémorisé.
- app/dashboard/check/page.tsx : formulaire, image, progression, score, violations, réécriture.

## Fonctionnement

1. La session Supabase est vérifiée par auth.getUser et les cookies sont rafraîchis par middleware.ts.
2. Les images JPEG/PNG/WebP sont réduites dans le navigateur à 1024 px de côté au maximum.
3. Le fichier est envoyé directement dans le bucket Supabase privé au moyen d'un jeton signé.
4. Le serveur vérifie l'identité, le droit de lire le média, le quota mensuel transactionnel et le rate limiting Cloudflare.
5. GPT-4o analyse en parallèle le texte et l'image ; les règles R1–R7 donnent des violations explicables.
6. L'IA produit des observations, pas une conclusion juridique automatique. Un logo n'établit pas l'existence d'une contrepartie.
7. Si le score de conformité est inférieur à 60, une réécriture consomme un quota distinct.
8. L'utilisateur confirme ou modifie la réécriture. Les données ne sont pas envoyées à un fine-tuning automatique.
9. Les coûts (en USD) sont estimés depuis les tokens, et enregistrés côté serveur.

## Limites exactes

- Les vidéos, les carrousels, le chat Mia fondé sur le RAG, l'export PDF, Stripe et Resend restent à développer.
- Un score de 100 ne constitue pas une attestation de conformité.
- Le hash couvre un manifeste contenant légende, plateforme et chemin privé du média, pas encore les octets du fichier.
- Les limites du plan Solo sont de 30 vérifications et 5 réécritures par mois ; Pro 500 et Studio 2000 au titre du fair-use.
- La base Supabase n'a pas encore été provisionnée depuis cette conversation : le projet existe mais les identifiants ne sont pas connectés.

## Installation Supabase obligatoire

- Exécuter les migrations 202611032001, 002, 003 et 004 dans cet ordre.
- Exécuter supabase/seed.sql, puis tests/sql/security_smoke.sql.
- Activer Auth email/password et définir l'URL du site Workers comme Site URL dans Supabase Auth.
- Ajouter NEXT_PUBLIC_SUPABASE_URL et NEXT_PUBLIC_SUPABASE_ANON_KEY comme variables de build et d'exécution Cloudflare.
- Ajouter SUPABASE_SERVICE_KEY et une NOUVELLE OPENAI_API_KEY uniquement comme secrets serveur Cloudflare.

## Incident de vérification — 3 novembre 2026

Symptôme : « La vérification a échoué. Le quota a été restitué. »
Diagnostic confirmé via Supabase : une vérification au statut failed,
aucune ligne ai_analyses, consommation mensuelle de check remise à zéro.
L'appel IA a échoué avant sa journalisation. La cause précise doit être
confirmée dans les logs du Worker Cloudflare, et non déduite de la base.

Correctif :
- Si l'appel texte échoue, les règles déterministes R1-R7 restent utilisables.
- Un contrôle dégradé retourne analysisMode=rules_only, signale clairement
  que le score est provisoire et ne produit pas de réécriture GPT.
- En l'absence d'appel IA réussi, le check est remboursé après sauvegarde.
- Une erreur de vision ou de réécriture entraîne un avertissement explicite.
- Les erreurs de base de données restent bloquantes : ne jamais falsifier un
  résultat comme réussi si l'archivage ou les quotas sont inopérants.
- Les logs [mentioncheck][ai_failure] contiennent uniquement le stade,
  la catégorie et le statut HTTP ; jamais le prompt ni les secrets.

Pour finir le diagnostic, aller dans Workers > mentioncheck > Observability
et filtrer [mentioncheck][ai_failure] après une nouvelle tentative. Si le statut
est 401, générer une clé OpenAI active ; si la catégorie est credit, vérifier
la facturation et les limites du projet OpenAI. Une connexion ChatGPT payante
n'assure pas la disponibilité ni les crédits de l'API OpenAI.

## Correctif cockpit — états des vérifications (2026-11-03)

Le tableau de bord affichait `En traitement` pour toute ligne sans score, y compris les lignes `failed`. L'affichage est désormais basé sur le statut stocké (`queued`, `processing`, `completed`, `accepted`, `kept`, `failed`) et la moyenne exclut les échecs même si une note résiduelle existe. Les tests unitaires de `lib/check-status.ts` protègent cette règle. Les contrôles réellement terminés affichent seuls un score ; une ancienne vérification échouée doit être relancée manuellement.

## Diagnostic IA après rétablissement Supabase — 3 novembre 2026

Les contrôles SQL confirment 1 vérification `completed` avec
`analysisMode=rules_only` et 1 ancienne vérification `failed`.
Le score 45/100 provient des règles automatiques, pas d'une réponse GPT-4o.
En mode `rules_only`, l'absence de réécriture ne prouve **pas** un quota atteint.

Correctif : le message « vérifie ton quota » est désormais conditionné par
le mode d'analyse ; les clés API manquantes sont détectées dans les logs
Workers sous `[mentioncheck][ai_failure]` et `category=missing_key`.

**Résolution opérationnelle** : vérifier la présence de `OPENAI_API_KEY`
dans Cloudflare Workers > mentioncheck > Settings > Variables and Secrets
(Production), avec type Secret. Vérifier ensuite la validité de la clé et
la facturation/limites du projet OpenAI. Ne jamais afficher la clé dans les
logs, les captures ou le dépôt. Si erreur 401, remplacer la clé ; si erreur
429 et `credit`, recharger/activer la facturation. Les logs Cloudflare
sont indispensables pour attribuer exactement la cause.
